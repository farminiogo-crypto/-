# نظام الكافيه — دليل للمساعد (CLAUDE.md)

نظام إدارة كافيه بنظام **الترابيزات والشيفتات**، دفع **كاش فقط** وبدون ضرائب.

## التقنيات
- **Backend:** Node.js + Express + SQLite (better-sqlite3) + JWT/bcrypt — مجلد `server/`
- **Frontend:** React 18 + Vite + React Router (عربي RTL) — مجلد `client/`

## أوامر التشغيل (من مجلد `cafe-system/`)
```bash
npm run setup     # تثبيت الكل + بيانات أولية + بناء الواجهة
npm start         # الخادم يخدم الواجهة على http://localhost:4000
npm run dev:server && npm run dev:client   # وضع التطوير (4000 + 5173)
npm run seed      # إعادة تعبئة قاعدة البيانات من الصفر
```
> ملف قاعدة البيانات في `server/data/cafe.db` (متجاهَل في git). لو غيّرت المخطط في `server/src/db.js` شغّل `npm run seed`.

## حسابات الدخول
- مدير: `admin` / `admin123`
- كاشير: `cashier` / `cashier123`

## الهيكل
```
server/src/
  db.js            # المخطط (SCHEMA) + initSchema
  seed.js          # بيانات أولية (drop + recreate + insert)
  auth.js          # signToken / requireAuth / requireAdmin
  routes/          # auth · menu · tables · orders · shifts · expenses · inventory · reports
client/src/
  api.js           # كل نداءات الـ API + إدارة التوكن (localStorage)
  main.jsx         # المسارات + حماية الصفحات
  pages/           # Login · POS · ShiftPage · Expenses · Inventory · Dashboard · MenuManager
  components/      # Layout (القائمة الجانبية) · Receipt (إيصال 80مم)
  styles.css       # كل التنسيقات (متغيرات ألوان في :root)
```

## قواعد ومنطق مهم
- **الفواتير:** `orders.status` = `open | paid | cancelled`. الإجمالي يُحسب في الخادم من `order_items` (لا يُعتمد على العميل).
- **الوصفات والمخزون (مترابط تلقائياً):** كل منتج له وصفة في `product_ingredients` (كمية لكل كوباية بوحدة المخزون الأساسية: جرام/مل/قطعة). عند **دفع** الفاتورة تُخصم المكونات من `inventory` داخل transaction وتُسجَّل في `inventory_moves`. تقدير "يكفي ≈X كوباية" = `quantity / qty_per_unit`.
- **العبوات:** صنف المخزون له `package_label/package_size` (كيس سكر = 1000 جرام). زر "خلّصت عبوة" (متاح للكاشير) يخصم عبوة كاملة ويسجّلها.
- **الشيفت:** واحد مفتوح فقط في نفس الوقت. المتوقع في الدرج = `رصيد البداية + مبيعات كاش − مصروفات`. لازم تُقفل كل الفواتير المفتوحة قبل قفل الشيفت.
- **المصروفات** مربوطة بالشيفت المفتوح (`shift_id`).
- **الأدوار:** المدير يشوف لوحة التحكم/إدارة المنيو/إدارة الترابيزات + صلاحيات تعديل المخزون؛ الكاشير يشوف الترابيزات/الشيفت/المصروفات/المخزون (قراءة + خلّصت عبوة).
- **الطباعة:** الإيصال مقاس 80مم عبر `@page` + `window.print()`.
- **الأيقونات:** تُختار من شبكة إيموجي ثابتة (`EMOJIS` في `MenuManager.jsx`) — مشروبات فقط، لا يوجد أكل.

## أعراف الكود
- الواجهة كلها عربي RTL — أي نص جديد بالعربي.
- الألوان من متغيرات CSS في `:root` بملف `styles.css` (مثل `--brand`, `--accent`).
- بعد أي تعديل على `client/` لازم `npm run build` عشان الخادم يخدم النسخة الجديدة.
- **`client/dist/` متتبَّع في git عمداً**: جهاز الكافيه ويندوز 7 (Node 16.20.2 — آخر نسخة له) وVite محتاج Node 18+، فالجهاز بياخد الواجهة مبنية جاهزة من الريبو. **أي تعديل client يتبعه build + commit للـ dist**.
- **توافق ويندوز 7**: كود السيرفر لازم يشتغل على Node 16 (ممنوع fetch/structuredClone/replaceAll في `server/src`). ملفات `.bat` بترميز ASCII بدون BOM وبدون PowerShell. أيقونات الواجهة إيموجي قديمة (≤2017) عشان تظهر على Chrome 109.
- الإيموجي في المنتجات اختياري (`emoji: null` مسموح) والمنتج بدونه يظهر بحرف اسمه.

## الحالة الحالية
النظام مكتمل ومترابط: POS بالترابيزات (فتح حساب باسم الزبون + إضافة ترابيزة من الشاشة)، شيفتات بجرد الدرج (اسم الكاشير إجباري)، مصروفات، مخزون بوصفات وخصم تلقائي عند البيع وسجل حركة وتقدير أكواب متبقية وعبوات (خلّصت كيس) ومستويي تنبيه (قرب يخلص/اطلب فوراً)، صفحة فواتير سابقة بفلتر وبحث وإعادة طباعة، إدارة ترابيزات (إضافة/تسمية/حذف)، لوحة تحكم بتنبيهات النواقص وتصدير تقرير شهري Excel، إدارة منيو بمكتبة أيقونات ومحرر وصفات، خط Cairo مدمج محلياً، تصميم متجاوب (موبايل ≤640px، تابلت ≤900px)، نسخ احتياطي تلقائي يومي.

### ملاحظات تقنية
- `db.js` فيه ترقيات تلقائية (migrations) — أي عمود جديد يُضاف بـ `ALTER TABLE` داخل `initSchema` بدون فقدان بيانات.
- `GET /api/orders` يرجع `{rows, count, total}` مع فلاتر `?date=&q=`.
- مكتبة الأيقونات `ICON_SET` في `MenuManager.jsx` (التكرار مسموح)، ووحدات المخزون `UNITS` في `Inventory.jsx`.
- الخط في `client/public/fonts/` (يُنسخ لـ dist تلقائياً).
- **حماية البيانات:** `npm run seed` يرفض المسح لو فيه فواتير — لازم `npm run seed:force`. نسخة احتياطية يومية تلقائية في `server/data/backups/` (آخر 30 نسخة) عبر `db.backup()` عند الإقلاع وكل 6 ساعات. الفواتير المدفوعة لا تُعدَّل ولا تُحذف أبداً.
- **تقرير شهري Excel:** `GET /api/reports/monthly.xlsx?month=YYYY-MM` (مدير) — 6 صفحات RTL عبر exceljs، والتنزيل من لوحة التحكم.
- **الطباعة الحرارية:** `@page size: 80mm auto` + عرض `72mm` للمحتوى + خط أسود سميك — كتلة `@media print` في آخر `styles.css`.

- **الطلب من الموبايل:** السيرفر بيسمع على 0.0.0.0، و`GET /api/settings/lan` بيرجع عناوين الشبكة المحلية (معروضة في صفحة الإعدادات). شاشة الترابيزات في POS بتتحدث تلقائياً كل 8 ثواني + عند focus عشان طلبات الموبايل تظهر على الجهاز الرئيسي. شريط دفع ثابت للموبايل (`.mobile-paybar` ≤640px).
- **الأنيميشن:** كتلة "حركات الواجهة" آخر `styles.css` — transform/opacity فقط. **تحذير:** متضفش `animation-fill-mode: both/forwards` لعناصر فيها `position: fixed` جواها (الـ transform الباقي بيكسر الـ fixed positioning).
- **ملاحظات الأصناف:** `order_items.note` (migration في `db.js`). `PATCH /orders/:id/items/:itemId/note`. إضافة صنف بتندمج فقط مع سطر بنفس المنتج و`note IS NULL` — الأصناف اللي عليها ملاحظات مختلفة تفضل سطور منفصلة. الملاحظة بتظهر في السلة والإيصال والفواتير.
- **صوت + تنبيه الطلب الجديد:** في `POS.jsx` — التحديث الصامت بيقارن بصمة الترابيزات المشغولة (عدد + إجماليات)؛ لو زادت يبقى طلب نزل من الموبايل → نغمة `AudioContext` + توست. `prevSigRef` هو خط الأساس.
